# LiveSupport 交互逻辑审查（2026-10-12）

## 审查范围

监控总览、主播详情、右键及托盘菜单、暂停恢复、人工任务、重连、账号管理、设置保存、添加主播、粉丝牌同步、二维码登录和退出。依据当前源码及隔离数据窗口检查；未用真实账号执行弹幕、点赞或佩戴测试。

## 发现与修复

| 问题 | 用户受到的影响 | 本次修复 |
| --- | --- | --- |
| 异常按钮仅对应账号暂停 | 查询失败、登录问题或连接异常时找不到入口 | 共用恢复状态映射，顶部按钮和底部说明一起变化 |
| 登录异常的底部提示仍写解除暂停 | 误导用户寻找无效操作 | 登录失效明确提供重新扫码；冷却仅解释时间，不提供绕过 |
| 右键菜单不遵守详情限制 | 暂停、下播及保护状态下仍能提交 | 共用操作规则，回调再次检查，并显示禁用原因 |
| 人工补齐或佩戴可以反复点击 | 重复提交或结果互相覆盖 | 按房间记录执行状态，禁用重复操作并显示等待时间 |
| 佩戴结果被下一次刷新覆盖 | 用户无法判断点击是否成功 | 房间详情保留最近操作结果 |
| 暂停、退出及设置应用直接阻塞界面 | 窗口暂时无响应，看起来点击无效 | 独立后台控制通道及非阻塞快照读取；退出等待未结束的 IO |
| 添加主播网络异常未恢复查询按钮 | 只能关闭窗口重开 | 错误回调恢复按钮；旧输入结果忽略；关闭后的回调安全丢弃 |
| 粉丝牌查询失败只能重开，登录跳转可能无效 | 没有可用的原地修复路径 | 重新查询按钮、扫码入口及明确的账号页跳转 |
| 保存成功与运行应用成功混为一谈 | 磁盘已写入，但运行未应用时仍显示成功 | 分开保存和应用状态，失败后恢复按钮并说明重试方法 |
| 二维码会话创建异常发生在捕获范围外 | 刷新按钮可能一直不可用 | 会话创建纳入异常处理，失败仍可刷新 |
| 界面异常仅显示一闪而过的文字 | 错误没有可见恢复入口 | 保存界面错误并显示“重试界面”，限制异常状态下的新写入 |

## 后续界面变更的验收规则

1. 每个错误、未知、过期状态，必须有明确下一步；自动恢复要显示条件或时间。
2. 禁用按钮必须说明原因；同一操作在详情、菜单和回调采用同一条件。
3. 耗时操作必须区分未提交、执行中、成功、失败；未收到结果不视为成功。
4. 同一房间的人工操作未结束前，不得因刷新或超时而重新放开重复提交。
5. 异常结果保留在详情；成功不代表平台奖励已经结算。
6. 关闭窗口、修改输入、切换页面后，迟到的结果不得错误应用到当前输入。
7. GUI 不等待监控锁或进程退出；网络池占满时，控制通道仍能接收操作。
8. 恢复不绕过账号保护、冷却或预算，也不输出凭证及设备标识。

## 验证与边界

`tests/test_interaction.py` 验证恢复路由、操作限制、冷却、暂停、登录、连接和查询异常、监控锁占用以及 IO 池占满后的控制操作。`tools/desktop_smoke.py` 检查实际 Tk 控件的菜单一致性、重复点击、持久错误反馈、查询失败及登录跳转，并检查默认和最小窗口布局。

不能保证平台网络请求立即返回，也不能保证重连后平台结算收益。已经发送的请求无法撤销；退出期间明确等待已提交操作结束。完整应用重启涉及运行会话，不将普通查询失败自动升级为重启或解除保护。
