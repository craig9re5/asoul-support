# 审计与分阶段重构计划

审计基线：2026-09-30，本机 61 项测试。历史代码保存在本机忽略目录 `build/refactor-baseline`，不发布该副本或运行数据。

## 审计结论

| 问题 | 证据 | 影响 | 处理 |
| --- | --- | --- | --- |
| 入口承担业务与 IO | heartbeat.py 1525 行；main 228 行、watch_room 202 行、弹幕阶段函数 122 行 | CLI、桌面和测试相互影响 | 独立应用服务、协议和 CLI |
| GUI 与业务耦合 | ui.py 1382 行；SettingsDialog 271 行、TrayUI 445 行 | 控件与网络错误语义不一致 | 视图、控制器、后台任务队列分离 |
| 重复逻辑 | 多份 HTTP、Cookie、粉丝牌、时间筛选和弹幕阶段实现 | 各入口规则漂移 | 共享 API、任务和配置服务 |
| 全局状态与隐式耦合 | worker.prepare 修改 heartbeat 模块、覆盖 _log；修改 sys.argv | 不同目录或线程串用配置 | 显式 AppContext、事件订阅、参数传递 |
| 错误被吞噬 | 15 个只含 pass 的异常处理；查询失败返回空列表或离线 | 误报成功、未开播或无新内容 | 区分 API、网络、认证、数据错误 |
| 深嵌套 | 桌面引擎与 UI 控制流最深约 7–8 层 | 难以推断分支与恢复 | 早返回、小函数、独立状态投影 |
| 并发边界不清 | GUI 多个 daemon 线程调用 Tk.after；设置读取后直接覆盖 | 线程越界、丢失更新 | 主线程回调队列、有限后台线程、配置原子合并 |
| 测试分布失衡 | 重点覆盖心跳；内容分页、异常、桌面业务一致性覆盖不足 | 回归难发现 | 增加适配器与共享服务契约测试 |
| 静态环依赖 | 基线未确认静态导入环；存在运行时模块修改与路径注入 | 动态耦合比导入图更隐蔽 | 核心禁止导入 desktop/scripts；统一兼容入口 |
| 魔法值与命名 | 协议字段、重试上限、中文阶段、历史 A-SOUL 默认名单混杂 | 配置边界与可选动作不清晰 | 集中策略常量、清晰的模型与单一成员配置 |
| SQL/IO/业务混杂 | 本项目没有 SQL；HTTP、文件 IO、UI 与业务混杂 | 单测需修改模块全局 | 明确基础设施和业务服务边界 |
| 发布材料过时 | 没有 LICENSE 文件；README 声明 MIT；文档路径与功能说明多次漂移 | 发布后难以安装或判断行为 | 许可证、来源说明、架构、贡献与发布文档 |

## 阶段与验收

1. **行为基线**：保留命令、参数和既有公开函数入口；记录审计；运行既有测试。
2. **共享核心**：配置/凭证/事件/HTTP/签名/API/任务/心跳/内容服务分层。核心依赖通过构造函数传入；禁止导入脚本或 GUI。删除重复业务实现。
3. **桌面一致性**：worker 和手动动作调用相同应用服务；UI 不修改模块或 argv；Tk 仅在主线程更新；引擎与状态投影拆分。验证动作开关、重启、跨日、任务失败、状态过期与多目录隔离。
4. **发布准备**：完整离线测试、结构检查、Windows 冻结程序诊断、无凭证打包、文件与历史敏感信息检查；补齐来源/许可证/构建/安全/贡献文档、CI 与桌面发布流程。推送至用户指定账号，保留上游归属。

不使用真实账号操作来验证重构。接口接收请求与任务实际记账分别表示；实验性点赞继续保持实验性说明。GUI 布局中的尺寸、颜色及协议规定的字段不机械消除，只把业务可配置值集中管理。

## 目标依赖方向

```text
脚本入口 / 桌面视图与调度
            ↓
       应用服务 AppContext
            ↓
     任务、心跳、内容业务服务
            ↓
       API 与协议适配器
            ↓
 HTTP / 文件存储 / 时钟 / OS 锁
```

兼容入口只适配旧函数，不保留第二套业务算法。重构结果与验证记录见 `docs/REFACTOR_RESULTS.md`。
