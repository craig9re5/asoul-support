# 账号异常保护与凭证存储

版本：2026.09.30.7。实现第一阶段异常保护与第三阶段凭证安全。第二阶段默认策略、单房间限制、账号每日总量与运行时长等待调研，未在本版调整。

## 请求与恢复

| 结果 | 行为 | 恢复条件 |
| --- | --- | --- |
| 只读请求网络失败 | 最多 3 次尝试，等待 1 秒、2 秒；连续失败冷却 60 秒 | 冷却结束后正常巡检 |
| HTTP 429、-509 或明确频繁提示 | 账号级暂停，至少 300 秒；服务器 Retry-After 更长时遵守 | 冷却结束，不允许提前解除 |
| -352、HTTP 412 或明确验证提示 | 作为异常拒绝处理；不推断具体平台原因 | 用户在平台检查/验证后，从托盘处理入口明确确认，并通过登录检查 |
| 登录失效 | 停止操作 | 认证成功或重新扫码；不能用本地确认按钮绕过 |
| 权限/禁言限制 | 停止账号操作 | 用户在平台处理后确认，并通过登录检查；如果接口仍拒绝则再次暂停 |
| 写请求超时、无效响应、HTTP 5xx | 结果未知，只发送一次，停止进一步写请求 | 点赞延迟查询任务进度；弹幕读取任务状态；用户核对后确认恢复 |

暂停状态由认证 UID 管理，在同一数据目录内跨进程/房间生效。暂停后新请求会被公共 HTTP 层拒绝；已在网络途中的请求无法撤销。未知结果允许只读核对，桌面给 worker 最多 20 秒完成核对后停止子进程。

点赞未知结果即使看到进度增长，也不会自动重放或直接宣布整项完成。人工恢复保留当日预算。桌面“暂停/恢复挂机”与账号保护暂停独立；普通恢复按钮不能解除账号异常。

CLI 使用 `python scripts/heartbeat.py --safety-status` 只读查看；在平台处理后运行 `--resume-safety --confirm-account-reviewed` 做登录检查并确认恢复。冷却期间不能提前恢复。

这些时间是项目的保守工程配置，不是平台认可的安全阈值。错误分类依赖响应代码及明确提示，可能需要随着接口变化维护，不能保证避免风控。

## 预算与入口

- 认证 nav 接口确认 UID 后建立本机会话别名；不能相信外部输入的 DedeUserID 来绕过认证。
- 每日任务仍保留原上限：每次弹幕巡检最多 16 次尝试、90 秒工作预算；每 UID/房间/北京时间日期最多 35 次弹幕尝试、3 次点赞任务执行。
- 底层 HTTP 写请求也预留并持久化预算：每 UID/房间/日最多 35 次弹幕请求、15 次点赞批次请求。单批点赞 1–30 次。底层上限覆盖兼容函数直接调用。
- 重新扫码、注销后重新登录和会话字段更新不会恢复当天 UID 预算。升级时迁移当前已认证会话的旧任务预算；无法关联账号的历史会话不会凭空归并。
- 手动补齐、CLI 点赞、签到自动模式和 --count 模式共用 DailyTaskRunner。--count 是本轮尝试上限，任务完成后不继续发送指定数量。
- 不同机器、不同数据目录不共享预算或异常状态。用户删除状态文件也会破坏这些本地约束。

## 凭证保护

Windows 使用 CryptProtectData/CryptUnprotectData，只有 UI_FORBIDDEN 标志，不使用扩大访问范围的 LOCAL_MACHINE。credentials.json 保存版本、后端标识和密文；密码学密钥由系统管理。解释见 [Microsoft DPAPI 文档](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

非 Windows 需要 `pip install 'asoul-support[secure-store]'`，仅接受系统 Secret Service/macOS Keychain 后端，拒绝明文、空后端及未知后端。相关平台要求见 [keyring 官方文档](https://keyring.readthedocs.io/en/stable/)。无凭据库的 CI 只在离线测试 runner 中注入测试存储；生产代码没有测试后端或明文降级。

旧 credentials.json 在读取时通过文件锁与原子替换迁移，不保存明文备份。安装器调用 EXE 本地迁移入口；指定旧 .asoul-support-data/.cookies.json 只有在成功保存并核对相同凭证后才删除。保护失败保留原文件并报错；无法解密时桌面仍能打开，已验证的扫码登录可替换旧密文。

退出登录清空凭证，停止旧 worker，清除账号及任务显示缓存、会话别名与旧凭证脱敏登记；保留 UID 预算和安全暂停。系统凭据库中的旧条目在原子替换成功后删除。

登录、弹幕、点赞、动态、视频和心跳共用匹配账号的 Cookie/UA 构造。心跳表单 UA 与请求头一致；服务器设备会话缺失时停止，不生成替代设备标识。带会话的请求只允许已使用的官方 API 主机，拒绝跨域重定向。

事件、桌面输出流和异常日志统一脱敏。已有历史日志、外部 HAR、剪贴板副本不自动重写；分享前仍需人工检查。DPAPI/Keychain 无法防止相同系统用户权限下的恶意程序，也不保证 Python 内存中的字节被立即擦除。

## 验收

离线测试覆盖：跨房间暂停、未知结果只写一次、点赞只读核对、有限退避、Retry-After、人工恢复约束、扫码更换后预算保留、旧预算迁移、线程与真实子进程共用预算、全部签到入口、现有 API 主机兼容、桌面暂停投影、凭证保护与注销、迁移失败保留、旧明文删除、Windows DPAPI 损坏密文拒绝、日志和分段输出脱敏、统一 Cookie/UA。

真实 Tk 控件测试验证账号保护暂停的表格与页脚。测试网络被禁止，没有为验收发送真实弹幕或点赞，也没有主动触发真实账号风控。
